Network Engineering

Objectives 1 and 2 include project explanations and evidence summaries.

Objective 1

Analyze personal and organizational requirements and design an appropriate networking architecture.

Project 1 · NTW275 Comprehensive Network Design

I compared MPLS and SD-WAN against the needs of a multi-site organization, including security, performance, scalability, and redundancy. Those requirements gave me a way to judge how each WAN option would support day-to-day operations and future growth. I used that comparison to propose an architecture that addresses both how sites connect and how the network can continue to operate when a link is unavailable.

Evidence · Comprehensive Network Design, pp. 2–3, Network Architecture and Addressing Operational Requirements.

Project 2 · NTW275 HealthCo Server Infrastructure Plan

I designed a hybrid infrastructure around a healthcare organization’s needs for authentication, storage, and database services. I used those needs to decide which functions the design would keep on an on-premises server and where cloud services could support the organization. This shows how I translated operational requirements into decisions about where services run and how the local and cloud environments work together.

Evidence · HealthCo Server Infrastructure Plan, pp. 2–4, covering on-premises and cloud service placement.

Objective 2

Develop cloud solutions emphasizing the benefits of remote infrastructure.

Project 1 · NTW216 AWS EC2 Automation

I adapted a Python script using Boto3 to launch an EC2 instance, check its state, and terminate it when I was finished. The lab screenshots show the instance running and later terminated. This demonstrates a practical benefit of remote infrastructure. I could provision computing capacity when I needed it, verify its state remotely, and release it through the same workflow. My lab report documents the changes I made to the script and credits the ChatGPT assistance I used.

Evidence · Script Functionality section and screenshots showing the running and terminated instance states.

Project 2 · NTS336 AWS Lambda Deployment and Testing

I deployed an AWS Lambda function and used a test event to confirm that the code ran in AWS and returned the expected response. The test demonstrates how a task can run on demand without requiring me to provision and manage a server for it. The function was intentionally simple, which made it easy to verify the part of the workflow I was testing, from invoking the deployed function to receiving its output.

Evidence · Testing the Function screenshot showing the expected hello, world! response.
