Student Innovation Project · UAT

Innovation Claim

My modular tower-mounted design combines fiber and DC power distribution to reduce long cable runs and improve maintainability. The completed off-tower prototype demonstrates circuit monitoring and remote notifications using LoRaWAN.

Project Description

Based on my experience with fixed wireless infrastructure, I developed two field-deployed distribution iterations. I then built and tested a standalone monitoring prototype with an Arduino MKR WAN 1310, three INA219 sensors, a RAK LoRaWAN gateway, and a Python notification service.

Verified Monitoring Results

The Arduino monitors incoming power and two loads, confirms fault and recovery states across three samples, retains serial diagnostics, and transmits state changes plus a heartbeat every 60 seconds. The Python receiver stores telemetry in SQLite and suppresses duplicate circuit notifications.

Updated project brief · November 2026

Revised SIP Brief

Problem

Separate tower-length fiber and DC power runs increase installation complexity and make fixed wireless sites harder to expand and troubleshoot. Individual circuit failures can be difficult to diagnose without a site visit.

Innovation

The modular tower-mounted distribution concept consolidates power and fiber near radios. The monitoring subsystem provides remote individual-circuit visibility, combining physical distribution improvements with notification capability.

Implementation

Three INA219 sensors report through I²C to an Arduino MKR WAN 1310. LoRaWAN delivers data to the RAK gateway built-in server, which forwards it over local Ethernet/MQTT to a Python receiver. The receiver writes SQLite records and sends Gmail SMTP alerts. A UPS keeps the monitoring electronics operational during the demonstrated input supply outage.

Results

Physical fault and recovery testing passed for all three monitored circuits. The recorded notifications show fault voltages around 5.6 V, normal voltages near 11.9 V, and a separate monitoring connection-loss alert.

Limitations and Next Steps

The completed hardware is a 12V proof of concept, not a production -48V protection system. INA219 sensors cannot directly monitor -48V. Production development requires appropriately rated sensing and circuit protection, environmental testing, reliability validation, and authenticated encrypted MQTT transport.

Benefit

Combining modular distribution with remote monitoring could reduce tower cabling and unnecessary diagnostic visits while improving fault visibility at remote sites.

Revised Direction: Arduino and LoRaWAN

The planned 12V test module will use an Arduino-based controller to monitor two demonstration circuits. Compatible LoRaWAN hardware will transmit circuit status and fault information through a gateway to a receiving application. A proposed parts list identifies candidate components, but final selections and configuration remain pending. Testing will verify the complete reporting path, including power loss and recovery. This work will also allow me to explore LoRaWAN networking and its associated security protocols.

Previous Cellular Concept

This image illustrates the previous Raspberry Pi and cellular approach. It is included for historical reference and does not represent the current planned hardware.

Power Supply Planning

The current prototype will use a main 12V DC supply for the demonstration circuits. A separate small UPS will support only the Arduino and sensing electronics. This arrangement will allow monitoring to continue when the main supply is switched off. The LoRaWAN gateway and supporting network services must remain powered and available to receive the outage report.
